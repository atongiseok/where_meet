# 🍻 where_meet — 오늘 어디서 만나?

모임 장소를 함께 정하는 **반응형 웹**입니다. 3명이 기능을 나눠 만들고, 이 저장소에 합쳐 **Railway**로 배포합니다.

- GitHub: `atongiseok/where_meet`
- 서비스 주소: https://wheremeet-production.up.railway.app
- 배포: Railway (권기석 계정, 이 저장소와 연결 → `main`에 올리면 자동 배포)

---

## 👥 역할 분담

| 담당 | 기능 | 작업 폴더 | 브랜치 이름 |
|---|---|---|---|
| **김정우 팀장님** (`jungwoo8703-bot`) | 회원가입·로그인(아톤 사내 계정·카카오), 닉네임 설정, 카카오톡 초대 링크 뿌리기, 회원탈퇴, **공유하기** | `src/auth/`, `src/share/` | `feature/auth` |
| **박수린 매니저** (`srpark99`) | 장소를 정하기 위한 여정 (설문으로 지역 정하기 → 지역 맛집 추천) | `src/journey/` | `feature/journey` |
| **권기석 이사님** (`atongiseok`) | 게시판(공지사항·회원게시판), GPS, 강제로 모임 장소 정해주기 / 전체 합치기·배포 | `src/board/`, `src/location/` | `feature/board-location` |

> 💡 **공통으로 쓰는 것**: 로그인한 사용자 정보(닉네임 등)는 모든 기능이 같이 써요. 그래서 **회원가입·로그인을 가장 먼저** 만들어 두면 나머지 기능을 붙이기 쉬워요.

## 🗂️ 폴더 구조 (안)

```
where_meet/
├── README.md          ← 지금 보는 문서
├── server.js          ← 서버 (공용, 수정 전 단톡방 공유)
├── package.json       ← 설치 목록 (공용)
├── src/
│   ├── auth/          ← 김정우: 회원가입·로그인·닉네임·탈퇴·카톡 링크
│   ├── journey/       ← 박수린: 설문 → 지역 결정 → 맛집 추천
│   ├── board/         ← 권기석: 공지사항, 회원게시판
│   ├── share/         ← 김정우: 공유하기 (링크 복사·카톡 공유)
│   ├── location/      ← 권기석: GPS, 강제로 장소 정해주기
│   └── common/        ← 첫 화면 + 같이 쓰는 것 (색상, 버튼 스타일)
```

**규칙: 내 폴더만 고치기.** 폴더의 `index.html` → `주소/폴더명/` 화면, `routes.js`(선택) → `주소/api/폴더명/` 서버 기능으로 자동 연결돼요. `common/`을 고쳐야 하면 단톡방에 먼저 알려주세요.

## 🛠️ 기술 스택 (합치기 전에 꼭 통일!)

세 명이 각자 다른 도구로 만들면 나중에 **합칠 수가 없어요.** (한 명은 한글, 한 명은 워드, 한 명은 PPT로 쓴 보고서를 한 파일로 만드는 상황)

| 구분 | 제안 | 비고 |
|---|---|---|
| 화면 | HTML / CSS / JavaScript (반응형) | 모바일 우선 |
| 서버 | Node.js + Express | Railway에서 바로 실행 |
| 데이터 | PostgreSQL | Railway에서 추가 |
| 로그인 | **아톤 사내 계정 로그인 + 카카오 로그인** | 아톤: **`@atoncorp.com` 이메일만 가입 허용** + 그 메일로 인증번호 보내 확인 (메일 발송 서비스 키는 Railway Variables에). 카카오: 카카오 디벨로퍼스 앱 1개를 같이 사용 |
| 지도·맛집 | **네이버 지도 API + 네이버 지역 검색 API** | 지도 표시·GPS는 네이버 클라우드 플랫폼(Maps), 맛집 검색은 네이버 개발자센터(검색 API) |

👉 첫 회의에서 위 내용을 확정하고 이 표를 업데이트해 주세요.

## 🔁 작업 → 올리기 흐름 (쉬운 버전)

**비유: 공동 보고서 쓰기**
- `main` = **최종본** (Railway에 자동 배포됨. 여기를 직접 고치지 않기!)
- `브랜치` = **내 작업용 사본**
- `커밋` = 중간 **저장**
- `Pull Request(PR)` = "제 파트 다 했어요, 최종본에 합쳐 주세요" **결재 올리기**

1. 내 브랜치에서 작업하기 (예: `feature/auth`)
2. 수시로 커밋해서 저장하기 (메시지 예: `회원가입 화면 추가`)
3. 다 되면 GitHub에서 **Pull Request** 만들기
4. 권기석 이사님이 확인한 뒤 `main`에 합치기 → Railway 자동 배포
